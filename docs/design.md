# 玩占 · 设计规范(design.md)

> **本文件是主视觉的唯一事实源。** 后续任何 UI 开发(小程序 / 看板 / 视频卡)必须严格遵循;
> 与本文冲突的旧样式一律以本文为准。想改设计:先改本文 + `dashboard/ui-proposal.html` 样机,
> 评审通过后再动代码(变更流程见 §10)。

---

## 1. 品牌基石

- **品名**:玩占(wán zhān)。出自《易·系辞》"君子居则观其象而玩其辞,动则观其变而**玩其占**"——正统出身,却自带把玩趣味。
- **气质四字**:**纸、墨、朱、章**(宣纸为底,墨为骨,朱砂点睛,印章为记)。
- **风格定位**:新中式素雅(参考"朴物商城"式纸感 UI),不是暗黑玄学风,也不是国潮大红大金。
- **设计三原则**(冲突时按序取舍):
  1. **可读优先** —— 命理信息密度高,任何装饰不得牺牲可读性;
  2. **素朴克制** —— 默认界面接近"一张纸",颜色少、装饰少;
  3. **仪式点睛** —— 仪式感集中在少数时刻(印章、盖章动效、翻卦),不铺满。

### 2.4 用色规则(MUST)

- **朱砂是唯一强调色**,单屏可见面积 ≤ 10%(印章、一颗 CTA、少量激活态);超出即违规。
- **红涨绿跌不可反**(中式口径):涨/吉 = 朱砂,跌/凶 = 松绿。K线、合婚加减分、任何涨跌语义一律如此。
- 禁用纯黑 `#000`、纯白 `#fff`;一切"黑白"用 `ink`/`card` 系代替。
- 正文对 `card` 底对比度 ≥ 7:1(`ink` 满足);`muted` 只用于辅助信息,不承载关键数值。
- 不引入上表之外的新色值。图表需要更多色阶时,由五行五色加透明度派生。

## 3. 字体系统

### 3.1 字体栈(不可替换)

```css
font-family: "Noto Serif SC", "Songti SC", "STSong", serif;   /* Web/看板 */
font-family: "Noto Serif SC", "Songti SC", serif;             /* 小程序 */
```
- **衬线(宋体)是品牌字感**,标题正文一律衬线;禁止用无衬线做标题。
- 数字/西文随中文字体栈,不单独换 sans。
- hyperframes 视频卡按其规范用 `@font-face + src: local()` 声明(见工作室 README)。

### 3.2 字号阶梯(小程序 rpx / Web px 对照)

| 层级 | 小程序 | Web | 字重 | 字距 | 用途 |
|---|---|---|---|---|---|
| Display(仪式) | 56-64rpx | 26-28px | 700 | 10-16rpx / 6-10px | hero 竖排、干支大字 |
| H1 页题 | — (用导航栏) | 24px | 500 | 2px | 看板页标题 |
| 标题 | 32rpx | 16-18px | 700 | 2-4rpx | 卡片标题、功能名 |
| 正文 | 28rpx | 14-15px | 400 | 默认 | 一切正文 |
| 辅文 muted | 24rpx | 13px | 400 | 默认 | 说明、出处 |
| 微标 | 20rpx | 11-12px | 400 | 1-2px | 英文小标、页脚 |

- **字重只允许 400 / 700**,禁用 100-300、500-600(500 仅限看板 H1 沿用)。
- 大字必须配宽字距(仪式感来自留白,不来自加粗);正文不加字距。
- **竖排(`writing-mode: vertical-rl`)只用于 hero 仪式文字**,任何功能性信息禁止竖排。

## 4. 间距与圆角

- **间距基数**:小程序 `8rpx`,Web `4px`。所有 margin/padding/gap 必须是基数整数倍。
- 常用阶梯:紧 `8/16rpx`(4/8px)→ 标准 `20/28rpx`(10/14px)→ 卡内 `28rpx`(20px)→ 区块 `36-44rpx`(22-28px)。
- 卡片外边距 `20rpx`(页面左右留白一致),卡内 padding `28rpx`(Web 20-22px)。
- **圆角**:卡片 `20rpx`/12px;方章图标 `18rpx`/9px;按钮 `16rpx`/9px;胶囊 pill `999`;印章 `12rpx`/6px。不新增圆角规格。
- 边框一律 1 物理像素(`1rpx`/1px)hairline,色用 `line`;禁止粗描边(方章图标 4rpx 描边是唯一例外)。
- 阴影只有一档:`0 2rpx 10rpx rgba(90,70,30,.05)`(Web `0 1px 3px rgba(90,70,30,.08)`);禁止多层/彩色阴影。

## 5. 组件规范

### 5.1 汉字方章图标(唯一图标体系)
- 功能图标 = **单个汉字 + 方章**:盘/运/合/卦/衣…… 新功能先定一个字。
- 两种形态:**描边墨章**(常规,4rpx `ink` 描边)/ **实底朱砂章**(每屏最多 1 个,给当日主推功能)。
- 尺寸 80×80rpx(Web 40×40px),字号 40rpx/20px,字重 700。
- **禁止引入 emoji、第三方图标库、彩色插图**做功能图标(页脚 tab 的极简符号◈◎◉除外)。

### 5.2 印章(品牌记号)
- 朱砂底 + `on-cinnabar` 字,双行竖读(玩/占),圆角 12rpx,84×84rpx。
- 出现场合:首页 hero、结果页"定论"时刻(配 `ani-stamp`)、视频卡。每屏 ≤ 1 枚。

### 5.3 按钮
- 主按钮:朱砂底 + `on-cinnabar` 字 + 字距 6rpx + `hover-class="btn-press"`(缩放 .95)。
- 每屏主按钮 ≤ 1;次操作用文字链(`muted` 色)或描边卡,不做第二颗实底按钮。

### 5.4 卡片 / Pill / 表格
- 卡片:`card` 底 + `line` 描边 + 标准圆角阴影;卡内不再嵌卡(最多两层)。
- Pill:`elevated` 底 `line` 描边;喜用=朱砂描边字,忌=`muted` 虚线描边(沿用现看板 `.fav/.bad`)。
- 表格:表头 `muted` 400,行分割 `line`;数值列涨跌按 §2.4 语义色。

### 5.5 表单
- 输入/选择器:`elevated` 底,聚焦描边变朱砂;label 用 `muted` 24rpx,置于控件上方 4rpx。

## 6. 动效规范

动效库唯一来源:`miniprogram/app.wxss`(Web 端对应各页实现),语义固定:

| 类 | 语义 | 时长/缓动 |
|---|---|---|
| `ani-rise` | 内容浮入(默认入场) | .5s cubic-bezier(.2,.7,.3,1) |
| `ani-flip` | 翻牌(四柱/卦宫揭示) | .55s 同上 |
| `ani-stamp` | 盖章(定论:等级/印章) | .55s cubic-bezier(.2,.8,.3,1.1) |
| `ani-pop` | 弹现(分数容器) | .4s cubic-bezier(.34,1.56,.64,1) |
| `breathe` | 朱砂呼吸(仅品牌字) | 3s 无限 |
| `d1`-`d6` | 交错延迟,步进 ~80ms | — |

- **每屏只允许一个"仪式动效"**(stamp/flip 二选一为主角),其余用 rise 陪衬。
- 结果重跑必须重放动画(先 `setData({r:null})` 再写入,既有约定)。
- canvas 逐帧动画(K线生长)时长 900-1000ms,easeOutCubic;低端机可降 DUR,不许砍中式红涨绿跌。
- 时长上限:任何入场序列(含交错)总时长 ≤ 1.2s;禁止循环装饰动画(breathe 品牌字除外)。

## 7. 版式与布局

- **页面骨架**(小程序):hero/表单卡 → 功能/结果卡 → 页脚免责声明(`faint`,居中,20rpx)。
- **免责声明"仅供文化研究与娱乐"每页必有,不可删**(联动 fork-guide ADR-9)。
- 留白即设计:区块间距宁大勿小;单屏信息组 ≤ 4 个卡片。
- **竖版视频卡(1080×1920)**:信息集中在上部 y 190-1200,**下 40% 必须留白**给人物/底片;
  同样遵循本色板与字体栈(纸感卡 + 墨字 + 朱砂点睛)。

## 8. 三端落地映射(改色只许改这三处源头)

| Token | 小程序 | 看板 | 视频卡 |
|---|---|---|---|
| 全部色值 | `miniprogram/app.wxss`(page/.card/.gold/.go/.glyph/.seal) | `dashboard/assets/style.css` 的 `html[data-theme="paper"]` 变量块 | `hyperframes-studio/wuxing-daily/index.html` `<style>` |
| 动效 | `app.wxss` 动效库 | 各页 + `cssVar()` 取色 | GSAP 时间线(遵循 §6 时长) |
| 品牌字 | `app.json` title + index hero | `common.js headerHTML` | 模板 vars |

- 严禁在页面内联新 hex(涨跌/五行语义色引用 §2 表值除外);发现内联色值视为技术债,重构进源头。
- 看板 SVG/canvas 取色一律 `cssVar('--xxx')`,不写死(既有坑表条目)。

## 9. 红线(违反=打回)

1. 红涨绿跌不可反(§2.4)。
2. "仅供文化研究与娱乐"不可删(§7)。
3. 朱砂单屏 ≤10%、实底朱砂章每屏 ≤1、主按钮每屏 ≤1。
4. 字体栈不可换、字重只用 400/700。
5. 不引入第三方 UI 库 / 图标库 / CDN 资源(零依赖是产品承诺)。
6. 新色值/新圆角/新阴影规格 = 必须先改本文,不许代码先行。
7. 深浅两主题(看板)下都必须可读——图表色改动要在两主题各验一遍。

## 10. 变更流程

1. 在 `dashboard/ui-proposal.html` 加新样机变体 → 用户确认;
2. 修订本文对应 token/规则(git 提交说明写动机);
3. 按 §8 映射表改三处源头 → 三端各自验证(小程序:微信开发者工具;看板:双主题;视频卡:抽帧);
4. 大方向变更(整套换风格)记入 fork-guide ADR。
